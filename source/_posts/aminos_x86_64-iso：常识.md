这里以 x86 PC 为例，概述从计算机上电到操作系统启动的基本流程，帮助建立操作系统运行环境的心智模型。

# 启动流程

## 开机

接入交流电后，主板的待机电源可使电源管理电路工作。按下电源按钮发出开机请求；主板与电源按平台时序启动主输出和 CPU 稳压供电。平台确认满足本平台要求的供电、时钟及复位时序后，解除 CPU 复位。具体条件和时序因平台而异。

## UEFI / BIOS

在典型 x86 PC 上，处理器复位后的架构状态使它从物理地址 `0xFFFFFFF0` 开始取指；该地址称为**复位向量（reset vector）**。平台硬件预先将包含该地址的区域映射到固件存储器；常见 PC 的固件存于主板 SPI 闪存，平台逻辑让 CPU 对该物理地址的取指访问到达固件。CPU 执行固件代码；UEFI 固件初始化平台后，根据启动项加载 EFI 系统分区（ESP）上的 EFI 应用程序，例如 GRUB。

在传统 BIOS 启动中，CPU 同样先从平台映射到固件的复位向量取指，执行保存在主板闪存中的 BIOS 固件。以从硬盘启动为例，BIOS 初始化硬件并选择启动设备后，通常将磁盘首扇区读入 RAM（传统流程常放在物理地址 `0x7C00`）并转交执行。采用 MBR 分区表时，该扇区包含 MBR 引导代码；使用 GRUB 时，这里通常只有少量初始代码，后续部分需另行定位并加载，常见位置是首分区前的嵌入区域。GPT 磁盘上，GRUB 可把后续代码放在 BIOS Boot 分区。具体布局取决于分区表和安装配置。

## GRUB

GRUB 是引导加载程序。固件启动 GRUB 后，它会读取配置（通常是 `grub.cfg`），并按配置中的菜单项定位内核文件；菜单项指定文件路径、启动协议和内核参数。选中菜单项后，GRUB 还可加载 `initrd`/`initramfs`，将相关文件放入内存，并按启动协议把控制权交给内核。

# 唯一可编写的代码

需要强调的是，从 CPU 的角度看，固件代码、引导程序代码和内核代码最终都要表示为 CPU 能解码的机器指令。可执行文件中的指令通常先加载到 RAM，或映射到 CPU 可取指的地址空间；固件指令也可能通过平台映射从闪存等存储器提供给 CPU。然后 CPU 再执行这些指令。

这些代码的关键差异在于他们的存储位置，它们的功能是被抽象的，非本质的。实际上，可以在内核代码中再写一个引导，跳转到另一个分区的操作系统。我们需要关注的是他们的可修改性。固件代码必须通过向固件存储芯片，发送底层协议修改；对于 UEFI 启动，GRUB 的引导程序代码也是一样。不过对于 BIOS 启动，可以在 ISO 中修改引导代码，因为他们都存储在磁盘上。而内核代码也存储在磁盘上，可以在磁盘上修改。

如果没有其他工具，只有工作用操作系统，我们只能修改磁盘镜像，这就是编写操作系统需要做的，也是唯一能做的。
